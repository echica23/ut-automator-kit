# ファイル名globによる対象選択（-G）

## コマンド

~~~text
ut -P "C:\projects\my-app" -coverage com.example.* -G "*ServiceImpl.java"
ut -P "C:\projects\my-app" -spec com.example.* -D docs/ -G "*ServiceImpl.java"
ut -P "C:\projects\my-app" -review com.example.* -J -G "*ServiceImpl.java"
~~~

-Gは全モード共通の任意引数。既存の対象指定で得た候補を、ソースファイル名で絞る。
パッケージ.*の下位パッケージも対象。完全修飾クラス指定とも組み合わせられるが、
そのファイルが一致しなければ0件となる。省略時は従来と同じ対象選択。
-Gだけで対象指定を省略できない。-Pは従来どおりMavenモジュールであり、
任意のソースディレクトリを-Pへ渡す機能ではない。

## globの範囲

初版はファイル名だけに対する簡易glob。パターンは引用符で囲んだ1個の文字列とする。

- * は0文字以上、? はちょうど1文字。それ以外の対応文字は文字どおり照合する。
- 拡張子を含むファイル名全体に一致させる。部分一致の検索ではない。
- 大文字・小文字を区別する。Windowsでも同じ。
- スラッシュ、バックスラッシュを含むパス指定、**、文字クラス[]、
  波括弧{}による選択・展開、エスケープ構文は初版では非対応。入力エラーとして報告する。
- 空文字、値省略、複数の-G、複数パターン指定はエラー。カンマ区切りも非対応。
- 正規表現として解釈しない。例えば.は任意文字ではなくドット。
- -includeは別名として追加しない。新しい既定フィルター設定も追加しない。

シェルの展開結果やOSごとのglobの差に依存させず、AIはこの規則で
列挙済みファイルの名前を照合する。globだけからクラス名を想像してはいけない。
利用する検索ツールのパターン仕様が異なる場合は、候補列挙後に上記規則で絞る。

## 解決順と0件時の処理

1. 引数を検査する。不正な-Gならprepareせず、入力エラーとして報告。
2. src/main/javaの既存対象範囲から候補を列挙する。パッケージ宣言・型と
   実際のファイルを確認し、既存の標準ソース配置制約に従う。
3. ファイル名を-Gで照合する。要求範囲外のパッケージやsrc/test/javaを追加しない。
4. 一致した候補にProject Rulesの除外・キットの既存制約を適用する。
   -Gで除外対象を復活させない。型の検証可否・内部クラス等の既存制約も変えない。
5. 具体的な完全修飾クラス一覧を実行前に報告し、通常はそのまま進める。
   同名ファイルはパッケージで区別し、完全修飾名で重複排除・整列する。
6. 単一モードでは残ったクラスだけをprepareへ渡す。mixでは[mix仕様](mix-mode.md)に従い、共通Rules除外後にタグ解決・モード別Rulesを適用して各グループのprepareへ渡す。依存クラスの必要な読込みは可能だが、
   読んだ依存先を勝手にテスト対象へ追加しない。

一致0件、またはRules適用後の全件除外ならprepare/executeを呼ばない。
パターンを緩めたり、元の全対象へ戻したりしない。
最終回答で要求範囲・パターン・候補数・一致数・Rules除外理由を示し、
「未実行・カバレッジ未計測」とする。レポート保存済みとは報告しない。
検索自体のアクセス失敗を一致0件と扱わず、探索不能/不完全として報告する。

## 記録・カバレッジ

report.mdの実行概要に元の対象指定と-Gを残す。参照範囲には候補数、
glob一致数、Rules除外数、最終対象数と具体的な対象一覧を示す。
globで外れたファイル全件の一覧は不要。Rulesによる除外は従来どおり理由を記録する。
未対応・未解決の一致対象があれば別記し、黙って対象から落とさない。
成功ケースの一覧や新しい説明用JSONは作らない。

カバレッジは最終対象の範囲として報告し、パッケージ全体の網羅率と混同しない。
要求範囲→glob一致→Rules除外→最終対象→実行確認済みを区別する。

## 実行基盤との関係

-Gは自然言語utコマンドを解釈するAI側の対象解決機能。
Java版の--targets、PowerShell版の-Targetsには解決済みクラス名だけを渡す。
ランナーへ-Gや未解決globを渡さない。run.json.targetsは最終対象のまま。
ランナー、JAR、設定スキーマの変更は不要。
同じキットを読み込んだ既存セッションでは、更新済み実行プロンプトを読み直す。
