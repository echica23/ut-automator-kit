# UT実行レポート

## 実行概要

モード、根拠種別（文書/Javadoc/実装）、コマンド、対象モジュール、実行ID、再試行IDと理由、完了/未完了を記載。
クラス数は要求対象・実行確認済み・未実行を区別し、対象一覧を示す。-G使用時は元の対象指定・パターン、候補数・glob一致数・Rules除外数・最終対象数を区別し、未対応・未解決対象も別記する。カバレッジの集計範囲が最終対象であることを明記する。
作業開始/終了時刻、経過時間、計測範囲・待機/中断の有無、
各試行のMaven test / jacoco:report時間（summary.jsonのmavenTiming）を記載。
時間は重複加算せず、未実行・未取得を0秒と混同しない。トークン記録は不要。

## 指摘・確認事項

FAIL / ERROR / SKIP / SPEC_UNKNOWN / RULE_CONFLICT / 未カバー / 未計測 / 対象除外を個別に記載。
該当なしならその旨だけ記載する。成功ケースの一覧は作らない。

- テスト：固定ID、対象・入力、固定期待値、実測値、仕様根拠（spec/review）、UTと実行証跡。
- 未確定・矛盾：影響ケースID、決められない期待値/ルール、参照箇所、理由、確認事項。
- 未カバー・未計測・除外：対象/ソース箇所、理由、影響範囲。
- reviewのみ：同じ指摘へ原因・ソース位置・根拠・確度・修正案を追記。推測は明示。
  正当なFAILは修正しない。修正案が未適用・未検証であることを示す。

## 集計

テスト件数・成功・失敗・エラー・skip。
SPEC_UNKNOWN / RULE_CONFLICTの未生成件数は実行件数と別枠にする。
全件未確定ならテスト未実行・カバレッジ未計測とする。

| 対象クラス | Line covered/missed/% | Branch covered/missed/% |
| --- | --- | --- |

分母0はN/A、XMLにない対象は未計測。未カバーの説明は指摘を参照する。

## 参照範囲・ルール適用

仕様参照ルート、探索完了/部分実施、読んだ資料・箇所と関連理由、未読/読取不能範囲と理由。
Project Rulesは未設定/適用/部分適用、読んだ節、適用概要と代表的なUT/レビュー箇所。
不採用・矛盾・除外は指摘への参照とし、説明を重複させない。
成功ケースの仕様対応はUTコメントで追跡する。

## 証跡・制約

生成UT、summary.json、change-check.json、Surefire XML、JaCoCo HTML/XML、必要なログへのリンク。
保護対象の変更確認、未完了事項・制約。
機械集計のPASSやカバレッジ100%だけで業務仕様適合を断定しない。
-Jの場合は参照ファイル・クラス/メソッド・Javadoc/通常コメントの区別・参照箇所、コメントの採用有無・理由と確認できた契約の範囲を示す。矛盾は双方の位置・主張と影響ケースを個別に記録する。
不一致は参照した契約（Javadocまたは補助コメント）と実装の不一致であり、業務上どちらが正しいかは別途確認が必要。
reviewの修正案は記載契約に従う場合の案として扱う。
